# 留存设计层：HKRR 与十二点节拍

本规范借鉴影视飓风公开内容中传播的 HKRR 与“时钟”概念，并针对“生活大于考研”的旁白驱动 Remotion 视频重新设计。只使用抽象方法，不复制第三方 Skill 的文字、模板、示例或受许可限制的资产。

它不是一种“影视飓风风格”，而是一层留存诊断：检查观众为什么愿意继续看，以及 Hook 作出的承诺是否在结尾兑现。

## 一、HKRR 的频道化定义

| 维度 | 本频道定义 | 可观察证据 | 常见误区 |
|---|---|---|---|
| H / Happiness | 情绪回报：惊讶、释然、被理解、看清规律或获得小胜利 | 观众产生“原来如此”“这说的就是我”“现在知道怎么做了” | 强行搞笑、煽情或加入无关爽点 |
| K / Knowledge | 知识回报：新机制、判断标准、证据或可执行动作 | 看完能复述一个判断，并能立刻用一次 | 堆概念、数据很多但没有决策价值 |
| R / Resonance | 共鸣：准确说出观众的身份、处境、担忧和重复行为 | 观众在开头或转折处完成自我识别 | 只喊焦虑、努力、上岸等空泛情绪词 |
| R / Rhythm | 节奏：句长、停顿、信息密度、画面状态和声音能量有层次变化 | 快速建立、适时落地、再推进；不存在长时间同速 | 把频繁切镜、缩放和音效误认为节奏 |

四个维度是整条视频的检查面，不要求每一句都同时命中。知识型视频至少要让 `K + Resonance` 成立；H 可以是“看清问题后的释然”，不必变成娱乐桥段；Rhythm 必须通过时间轴设计，而不是最后补转场。

## 二、Hook 承诺账本

先写清四句话：

1. `viewer`：这条视频在对谁说？
2. `tension`：他正在承受什么冲突、代价或错误判断？
3. `promise`：继续看能获得什么新判断或解决办法？
4. `payoff`：结尾用哪句话、哪条规则或哪个动作兑现？

Hook 只负责建立对象与张力，不提前塞满解释。Hook 结束后下一拍直接亮出主题观点句；正文持续分期偿还承诺，结尾必须完整兑现，不能只用 CTA 代替结论。

## 三、十二点节拍图

把完整视频归一化为十二个区间，用 `0/12` 到 `12/12` 的边界检查留存。它是诊断坐标，不是十二个镜头、十二句文案或十二次转场。

### 五个结构锚点

| 位置 | 任务 |
|---|---|
| `0/12` | Hook：对象、冲突或代价立即成立 |
| `3/12` | 第一次主刷新：揭示机制、反转常识或给出第一份证明 |
| `6/12` | 中点升级：问题变深，或从解释切换到方法 |
| `9/12` | 行动转折：把证据变成选择、规则或步骤 |
| `12/12` | 完整偿还 Hook 承诺，再给内容相关 CTA |

其余位置用于保持注意力，可通过新例子、新证据、新关系、视觉状态变化、短问题或情绪松紧完成。连续多个点都只是同一种解释时，应合并、删减或改变表达层级。

### 什么才算一次有效刺激

- 新冲突：观众原有判断受到挑战。
- 新证据：数字、真题、行为记录或对比进入。
- 新关系：原因与结果、投入与收益、想象与现实被连接。
- 新动作：观众获得一个可以立刻执行的判断或步骤。
- 新视觉状态：同一对象发生有含义的保留、删除、转移、压缩或选择。
- 情绪转折：紧张变释然、怀疑变确定、受挫变可行动。

以下不算有效刺激：单纯切镜、缩放、弹跳、音效、花字、重复字幕、无新信息的 B-roll。

## 四、按视频长度使用

- 60 秒以内：允许把相邻节拍合并，优先保证 Hook、第一次刷新、中点升级、行动和结尾偿还。
- 60—180 秒：默认绘制完整十二点节拍图。
- 180 秒以上：先按章节建立大节拍，再在每章内部做局部留存检查；不要把整条长视频硬切成十二镜。

所有时间点最终以锁定旁白为准。写稿阶段只能给出比例和暂估秒数，不能把估算当成正式分镜时间。

## 五、与信息动画十二原则的关系

```text
HKRR：这条视频给观众什么价值
十二点节拍：价值和刺激在什么时候出现
信息动画十二原则：每次变化怎样运动得清楚、自然、有吸引力
```

留存设计先决定“为什么变化”，动画原则再决定“怎样变化”。不得为了填满十二点而添加没有信息增益的动画。

## 六、分镜字段

爆款或留存优化任务的分镜增加：

- `clockPoint`：`0/12`—`12/12`
- `hkrr`：本节拍主要提供哪一类价值
- `stimulus`：新冲突、证据、关系、动作、视觉状态或情绪转折
- `promisePayment`：它偿还了 Hook 承诺的哪一部分
- `reasonToContinue`：这一拍之后，观众还想知道什么

推荐使用如下数据结构，但不强制具体实现：

```ts
type RetentionBeat = {
  atSeconds: number;
  clockPoint: `${number}/12`;
  hkrr: Array<'H' | 'K' | 'R' | 'Rhythm'>;
  stimulus: string;
  promisePayment: string;
  visualChange: string;
};
```

## 七、留存 QA

- Hook 是否在最短时间内同时命中对象与冲突/代价？
- Hook 后是否立即亮出主题观点，而不是继续吊胃口？
- `3/12`、`6/12`、`9/12` 是否发生结构性推进？
- 是否出现连续多个节拍只有解释、没有新关系或新行动？
- 情绪和语速是否一直处于同一档位？
- 是否把剪辑动作错误地算成了内容刺激？
- 结尾是否真正偿还 Hook，而不是突然开始关注引导？
- CTA 是否说明继续关注能获得什么，并显示 `@生活大于考研`？

若某个节拍没有新的继续观看理由，不自动补素材；先判断应合并、删减，还是把后面的有效信息提前。
