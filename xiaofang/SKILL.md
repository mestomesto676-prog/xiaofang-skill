# 小方 · Xiaofang

这是「生活大于考研」唯一的视频制作 Skill。不要再把白板动画和 Remotion 十步法当成两套端到端流程；本 Skill 用一套十步法编排全部制作，并按镜头选择纸雕素材、统一骨架或代码动画。

默认成片：`1080×1920`、30fps、带字幕发布版、SRT、封面、发布材料和可复用工程。

## 品牌锁

开工先读 [品牌与角色系统](references/brand-system.md)。不可变项：

- 唯一品牌主角是**小方**；不另造吉祥物或替代主角。
- 默认视觉是**纸雕/折纸/布纹世界＋粗线条黑白小方**。
- 小方的角色真源是 `references/小方-IP设定图.jpg`、`assets/xiaofang-reference.jpeg` 和 `scripts/engine/lib/rig_xiaofang.js`。
- 生图不能重新设计小方。关键动作由统一骨架或分层素材控制；生图主要负责场景、道具、材质与氛围。
- 准确文字、数字、图表、流程和时间变化始终由代码渲染。
- 画风可以随内容调整轻重，但不得改变小方的名字、头身结构、黑白身份和粗线轮廓。

一句话标准：**纸雕负责质感，小方负责品牌，代码负责准确。**

## 唯一工作流：十步法

严格按以下顺序工作：

**钩子 → 文案 → 旁白 → 分镜 → 素材 → 视频 → 字幕 → 封面 → 发布材料 → 交付验收**

具体阶段、产物和返工边界见 [十步制作流程](references/ten-step-workflow.md)。

- 钩子和文案是用户重点确认点。用户已经明确认可全文时，将其视为锁定稿，不重新改写。
- 分镜、素材和视频是 Agent 的主要创意与执行区；普通视觉选择不反复打断用户。
- 后一阶段只能使用前一阶段已经锁定的产物。
- 第十步只审计和定向返工，不继续添加新观点或无目标换风格。

## 每镜媒介决策

分镜前必须读 [视觉媒介决策](references/visual-media-decisions.md)。每镜在分镜表中填写：

- 信息任务
- 媒介：`text` / `code` / `image` / `hybrid`
- 画面发生了什么
- 屏幕文字
- 小方动作及控制方式：`rig` / `layered` / `static`
- 颜色语义

快速判断：

| 信息任务 | 首选实现 |
|---|---|
| 准确结论、术语、提示词、数字 | 代码文字 |
| 变化、因果、顺序、比较 | 代码动画 |
| 氛围、复杂静态环境、特殊道具 | 生图或现有图片 |
| 小方拿、推、走、指、看、反应 | 统一骨架或分层素材 |
| 复杂纸雕场景中发生关键变化 | 生图底图＋小方骨架＋代码动画 |

如果“画面发生了什么”只能写成“出现图标”或“小方站着指图标”，重做视觉隐喻。

## 两种镜头语法，不是两套 Skill

### 纸雕混合镜头（默认）

用于封面、Hook、主题观点、关键转折、情绪高潮和需要记忆点的场景。制作前读 [纸雕混合管线](references/papercraft-pipeline.md)。

- 图片：纸张空间、真实物品、复杂光影、静态隐喻。
- 小方：骨架或分层纸雕零件；动作前后必须能与物体正确接触。
- 代码：标题、数字、图表、卡片内容、局部变化和精确时间轴。

### 白板代码镜头（信息段）

用于流程、因果链、图表、计时、排序和需要快速修改或批量生产的段落。

- 保持暖纸底、粗黑线、小方和单一蓝色语义，不发展成另一套视觉品牌。
- 可用 `scripts/xf.sh new/render/stills/qa/gate/frames/web` 和参数化引擎。
- 一整块板优先用相机移动和对象延续，不用苍白换页。

一支视频可以交替使用两种镜头语法，但必须共用同一个小方、字体、颜色语义和安全区。

## 运动与留存

- 设计动作前读 [运动决策](references/motion-decision-system.md)；需要精修时再读 [信息动画原则](references/motion-principles.md)。
- 每镜只有一个主动作；删除动作后信息不损失，就删除。
- 动作先定义 `stateA → mainAction → stateB → settle`，再写缓动。
- 做 Hook、留存或爆款优化时读 [留存设计](references/retention-design.md)。转场、缩放和音效本身不算新刺激。

## 字幕、版式与安全区

- 字幕来自锁定原稿，ASR 只提供时间戳；用 `scripts/align_captions.py` 输出字幕数据和 SRT。
- 字体、字号和行距见 [排版系统](references/typography.md)。
- 抖音安全区见 [竖屏安全区](references/vertical-safe-area.md)。核心标题、数字、小方面部和关键动作必须在中部偏左的安全舞台内。
- 生图不得内嵌必须准确阅读的中文、数字、选项和图表。

## 旁白

- 固定音色和语速见 [旁白配置](references/voice-profile.md)。
- 用户提供音频时直接使用；调用 MiniMax 前必须具备用户授权和有效密钥，使用 `scripts/minimax_tts.py`。
- 没有授权或密钥时，不调用外部 TTS；可以继续完成无声预览、分镜和画面。

## 实现与工具

- `scripts/engine/`：小方参数化骨架、纸张/蜡笔绘制和白板代码动画。
- `compose/remotion/`：封面、栏目包装和精确文字层。
- `compose/hf/`：字幕、外部配音、BGM 闪避和最终合成。
- `scripts/xf.sh setup`：安装本 Skill 内部固定版本的 Node/Remotion/HyperFrames 依赖，不全局安装。
- 若已安装 `remotion-best-practices`，编码时可按任务读取其当前 API 参考；它只补充技术规范，不改变本 Skill 的品牌和十步流程。
- `video-shotcraft` 仅是可选单镜头配方库；未安装时不得阻塞制作。

## 硬规则

- 视频、图片和工程文件不放进 Obsidian；Obsidian 只存纯文字说明。
- 新系列或长片在锁定文案后，先交付完整分镜供用户确认，再大规模制作素材和整片代码。
- 不擅自调用付费服务，不把密钥写入文件、日志或交付物。
- 代表帧必须检查小方比例、眼睛、线宽、手物接触、文字碰撞和平台安全区。
- 最终 MP4 用 `scripts/xf.sh web` 输出兼容版，并用 ffprobe 与完整解码检查。
- 回报中明确区分已验证、未验证和已知不足。

## 完成标准

- 同一支片中，小方跨镜头仍是同一个角色。
- 纸雕场景没有压过知识重点，代码文字和数字准确。
- 每个动作都有信息目的，小方与物体接触可信。
- 旁白、画面、字幕、封面和发布文案偿还同一个内容承诺。
- `production-manifest.md` 能对上全部镜头、素材、来源、帧范围和输出版本。
- 最终审计结论为 `Approve`；存在 P0 或关键 P1 时不得交付。

常见工程问题见 [踩坑清单](references/pitfalls.md)。
